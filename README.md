# high-level-design

System design notes I kept while prepping. Two parts:

- `concepts/` — the building blocks (load balancing, caching, sharding, replication, CAP, consistent
  hashing, message queues, CDN, rate limiting, API gateway, SQL vs NoSQL, indexing, estimation).
- `case-studies/` — the usual interview systems worked end to end: requirements, capacity numbers, API,
  data model, architecture, deep dives, and where it breaks at scale.

The estimations use real numbers rather than hand-waving, and the case studies point back at the concept
notes instead of re-explaining the same pattern every time.
